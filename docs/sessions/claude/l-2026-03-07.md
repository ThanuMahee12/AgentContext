### 1. SQL Injection Risk (Medium Risk) - Fixed
**File:** `duckdb_ops.py`

- Added `_validate_and_escape_path()` function
- Validates paths contain only safe characters (`[\w\-./\']+`)
- Rejects shell metacharacters (`$`, `;`, `|`, etc.)
- Escapes single quotes for SQL

```python
_SAFE_PATH_PATTERN = re.compile(r"^[\w\-./\']+$")

def _validate_and_escape_path(path: str) -> str:
    if not _SAFE_PATH_PATTERN.match(path):
        raise ValueError(f"Unsafe characters in path: {path}")
    return path.replace("'", "''")
```

## Session 3 (Continued)

### Code Review Feedback - New Issues

#### 1. DELETE+INSERT Atomicity - Fixed
**File:** `duckdb_ops.py:339-376`

**Problem:** DELETE + INSERT was not atomic. Crash between DELETE and INSERT would lose records.

**Fix:** Wrapped in transaction with BEGIN/COMMIT/ROLLBACK.

```python
conn.execute("BEGIN TRANSACTION")
try:
    # DELETE existing records
    conn.execute(f"DELETE FROM canonical.filemetadata WHERE ...")

    # INSERT shard records
    conn.execute(f"INSERT INTO canonical.filemetadata ...")

    conn.execute("COMMIT")
except Exception:
    conn.execute("ROLLBACK")
    raise
```

### Crash Recovery Flow

| Crash Point | Shards | Canonical | Recovery |
|-------------|--------|-----------|----------|
| During writes | Partial | Unchanged | Re-merge shards |
| During DELETE | Exist | Unchanged (ROLLBACK) | Re-merge shards |
| During INSERT | Exist | Unchanged (ROLLBACK) | Re-merge shards |
| After COMMIT | Exist | Updated | Re-merge (idempotent) |
| After cleanup | Gone | Updated | Nothing to do ✓ |

Shards act as write-ahead log. Data safe until merge + cleanup complete.
