#### 3. Files Stuck in env* Directories Investigation

**Branch:** `fix/restore-mtime-reprocessing`

**Problem:** Multiple datasets had files stuck in env* directories after Feb 12, 2026. Files not moving from env directories to bronze layer.

**Root Causes Identified:**

| Issue | MR | Description |
|-------|-----|-------------|
| 1-hour lookback | !352 | Default lookback changed from 24h to 1h - files older than 1 hour never discovered |
| No mtime reprocessing | !523 | Removed `file_needs_reprocessing_by_mtime` check - resupply files not auto-reprocessed |

**Affected Datasets (143 files total):**
- 80 files: jp_morgan/global_equities_machine_readable_research_reports_cwiq_pipe
- 28 files: factset/factset_all_cwiq_pipe
- 16 files: lseg_refinitiv/reuters_fundamentals_cwiq_pipe
- 8 files: crunchbase/firmographic_cwiq_pipe
- 6 files: sp/transcripts_cwiq_pipe
- 4 files: sp/capital_iq_kd_cwiq_pipe
- 1 file: lseg_refinitiv/street_events_cwiq_pipe

**Fix Implemented:**

Changes to `data_alchemy/main.py`:
1. Added import: `file_needs_reprocessing_by_mtime`
2. Restored mtime check in file filtering logic (lines 940-944):

```python
else:
    # Check if file has been updated since last processing
    # This handles resupply files delivered to the same path
    if file_needs_reprocessing_by_mtime(db_engine, fp, "bronze"):
        raw_files_needing_bronze.append(fp)
```

**How mtime Reprocessing Works:**
- `file_needs_reprocessing_by_mtime` compares current file mtime with stored `delivery_time`
- If `current_mtime > stored_delivery_time` → file gets reprocessed
- Handles resupply scenario: same path, newer file content
