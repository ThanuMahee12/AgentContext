### Key Design Decisions

- **Cross-platform:** No ctypes/advapi32, `Path.owner()` with graceful fallback to "N/A"
- **SHA256 only:** Dropped MD5, single-pass 8KB chunks
- **Compound extensions:** `Path.suffixes` joined (`.tar.gz` support)
- **Size as raw bytes:** No parse_size/format_size helpers
- **Filter order:** date -> time -> size -> path_pattern -> name_pattern -> unique (last)
- **Typer + Rich:** Not argparse + tabulate as originally planned
- **Dependencies:** typer, rich, pandas (unpinned)
- **`--lookback` default `1H`:** Uses `filter_by_past_duration`, overridden when `--scan-start`/`--scan-end` provided

### Debugging / Issues Encountered

1. **requirements.txt UTF-16 encoding:**
   - `pip freeze` on Windows generated UTF-16 with BOM
   - Linux pip error: `ERROR: Invalid requirement: '��click==8.1.8'`
   - Fix: Rewrote file as clean UTF-8

2. **requirements.txt version pins incompatible cross-platform:**
   - Pinned `markdown-it-py==4.0.0` requires Python >=3.10, Linux server had older Python
   - Fix: Removed all version pins, kept only 3 direct deps (`typer`, `rich`, `pandas`)

3. **Path separator mismatch on Windows:**
   - `fnmatch` uses `/` but `relative_path` on Windows uses `\`
   - Fix: Normalize `\\` to `/` before `fnmatch` in `filter_by_path_pattern` and `_scan_single_target`

4. **`datetime.now()` called per file in `filter_by_past_duration`:**
   - Cutoff time shifted during scan, inconsistent results
   - Fix: Compute cutoff once at filter creation time

5. **Duration regex matched empty string:**
   - Pattern `(?:(\d+)D)?(?:(\d+)H)?(?:(\d+)M)?$` accepted `""`
   - Fix: Added `^` anchor + `any(match.groups())` check

6. **Shell glob expansion on Windows test:**
   - `--path-pattern "*.py"` expanded by shell before reaching Python
   - Workaround: Not an issue on Linux

7. **Python <3.10 `X | None` syntax error on Linux:**
   - `TypeError: unsupported operand type(s) for |: 'type' and 'NoneType'`
   - Fix: Added `from __future__ import annotations` to scanner.py, filters.py, utils.py, main.py

### Performance Optimization Session (Session 2)

#### Three-Tier Filter Cascade (pushed)
Reordered filtering in `_scan_single_target` to short-circuit by cost:

| Tier | Cost | Checks | Short-circuits |
|------|------|--------|----------------|
| **0 — Free** | Zero I/O | `name_regex`, `path_pattern` | Before any stat call |
| **1 — Cheap** | 1 stat syscall | date, time, size filters | Before MIME/owner |
| **2 — Expensive** | File I/O + OS calls | owner, MIME enrichment | Only for matches |

#### Two-Phase Metadata (pushed)
- `extract_metadata_stat(file_path, base_dir, file_stat)` — builds FileMetadata from pre-computed stat, `owner=""`, `mime_type=""`
- `enrich_metadata(metadata, file_path)` — fills owner + MIME on existing FileMetadata
- `extract_metadata()` — unchanged convenience wrapper calling both

#### os.walk() Replaces glob() (pushed)
- `_walk_files()` uses `os.walk()` instead of `pathlib.glob("**/*")`
- `_list_files()` uses `os.scandir()` for non-recursive scans

#### Depth-2 Directory Expansion (pushed)
- `_expand_dir()` recursive helper splits directories up to `max_depth=2`
- Leaf directories added as single recursive scan units
- Non-leaf directories split further for parallelism

#### dir_cutoff Mtime Pruning — FAILED, REMOVED
- **Attempted:** Skip directories with mtime < lookback cutoff during both expansion and os.walk
- **Problem:** On server's NFS filesystem, directory mtime does NOT reflect child file modifications. Only reflects file add/remove, not content changes.
- **Result:** 0 files found (false negatives). Removed entirely in follow-up commit.
- **Lesson:** Directory mtime pruning is unreliable on network/shared filesystems
