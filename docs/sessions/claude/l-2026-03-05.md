### 2. SQLite Parallelism Discussion with Team
Full discussion captured in `~/AgentContext/docs/discussions/sqlite-parallelism-bottleneck.md`

**Problem:** SQLite DB locking under parallel workers. Single DB = contention.

**Agreed Solution:**
1. Each worker gets its own SQLite for writes only (`worker_db/w001.sqlite`, etc.)
2. All reads happen BEFORE phase starts — main thread queries canonical + worker shards via DuckDB
3. No DB reads inside per-file handler logic — workers only write
4. Merge worker shards into canonical at end of cycle using DuckDB with `n_threads = -p`
5. If merge latency issues, skip merging — just read all shards at phase start via DuckDB

**Team:** Wingate ✓, Kumaran ✓, Thanu implementing

## Key Learnings

### Architecture Flow
```
┌──────────────────────────────────────────────────────────────┐
│ PHASE START (Main Thread)                                    │
│    DuckDB reads ALL: canonical + worker_db/*.sqlite          │
│    → files_to_process, already_processed, existing_outputs   │
└──────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌──────────────────────────────────────────────────────────────┐
│ FILE OPERATIONS (Workers - Parallel)                         │
│    NO DB reads inside file processing                        │
│    Just file ops: move, transform, compress                  │
└──────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌──────────────────────────────────────────────────────────────┐
│ PHASE END (Workers - Own DB)                                 │
│    Worker 1 → WRITE worker_db/w001.sqlite                    │
│    Worker 2 → WRITE worker_db/w002.sqlite                    │
└──────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌──────────────────────────────────────────────────────────────┐
│ CYCLE END (Main Thread - DuckDB Merge)                       │
│    SET threads TO N;                                         │
│    INSERT INTO canonical SELECT * FROM worker shards         │
│    DELETE worker_db/                                         │
└──────────────────────────────────────────────────────────────┘
```

### Handler Changes
```
BEFORE (reads + writes mixed):     AFTER (write-only):
handler() {                        handler(context) {
  is_file_processed()  ❌            check context (in-memory)
  get_outputs()        ❌            file_io()
  file_io()                          upsert() ✅
  upsert()             ✅          }
}
```
