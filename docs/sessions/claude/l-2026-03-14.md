## SQLite Race Condition Fix

### Issue
```
OperationalError: table filemetadata already exists
```
Occurred at 2026-03-14 02:20:25 for `sp/transcripts_cwiq_pipe` dataset.

### Root Cause
Race condition when multiple workers start on a new day:
1. Worker A: `db_file.exists()` → `False`
2. Worker B: `db_file.exists()` → `False` (race)
3. Worker A: `create_all()` → creates table
4. Worker B: `create_all()` → **ERROR: table already exists**

SQLAlchemy's `create_all()` does NOT use `IF NOT EXISTS` in SQL - it uses Python-level reflection (`checkfirst=True`).

### Self-Healing Behavior
- Error is self-healing - next cycle succeeds automatically
- Once DB file exists, `db_file.exists()` check passes and skips `create_all()`

### Fix Implemented
**Branch:** `fix/sqlite-table-exists-race-condition`
**MR:** https://git.codewilling.com/data/cwiq-pipe/data-alchemy/-/merge_requests/642 (Draft, target: dev)

```python
# Before (line 524-525 in db.py)
if not db_file.exists():
    SQLModel.metadata.create_all(engine)

# After
from sqlalchemy import inspect
inspector = inspect(engine)
if "filemetadata" not in inspector.get_table_names():
    SQLModel.metadata.create_all(engine)
```

Uses SQLAlchemy inspector to check at database level instead of filesystem level.

## DuckDB Memory Configuration

### Issue
System load increase with 5 services running `PARALLEL=-1` on 32GB machine.

### Root Cause
Default `DUCKDB_MEMORY_LIMIT=24GB` is too high for multi-service deployments.

### Solution (Config Only - No Code Change)
Set in `.env` file:
```bash
DUCKDB_MEMORY_LIMIT=2GB
```

### Memory Calculation for 32GB Machine (5 Services)

| Component | Calculation | RAM |
|-----------|-------------|-----|
| Workers | 12 × 1GB | 12GB |
| DuckDB | 5 × 2GB | 10GB |
| OS/Buffer | - | 4GB |
| **Total** | | **~26GB** |

### Environment Variable Reference
```bash
DUCKDB_MEMORY_LIMIT=2GB   # Default is 24GB (too high for multi-service)
PARALLEL=2                 # Or 3, to limit workers per service
```

## Key Learnings

1. **SQLAlchemy `create_all()` is NOT atomic** - uses Python-level reflection, not SQL `IF NOT EXISTS`
2. **NFS race conditions** - filesystem checks (`db_file.exists()`) can race on NFS
3. **Self-healing systems** - understand when errors auto-recover vs require intervention
4. **Multi-service memory planning** - default configs may assume single-service deployment
