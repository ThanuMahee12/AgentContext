## Branch: feature/local-db-heal-sweeper → MR !1105

### Summary
Fixed root cause of bbocax `no such table: filemetadata` daily Slack alerts (ClickUp 868k5ab47).

### Root cause confirmed on prod07
- 261 SQLite DBs stuck on local disk back to Dec 2025 (should be on cwiqfs)
- `rotate_local_dbs` checks mtime — silver writes to old bronze partitions keep refreshing mtime → rotation never triggers
- 12 bbocax services restart together → all open 261 old local DBs via `--backfill 3` → workers race to query `filemetadata` before `create_all` commits schema

### Fixes
1. **`db.py:rotate_local_dbs`**: use folder date (YYYY/MM/DD from path) instead of mtime to determine rotation eligibility. Old-date folders rotate regardless of mtime — eliminates stuck-DB accumulation
2. **`main.py`**: moved `rotate_local_dbs` from synchronous main-cycle call to background `daemon=True` thread (same pattern as DQ) — zero impact on main process
3. **`db_config.py` + `db_config.yaml`**: added `DB_ROTATION_CYCLE=3` — rotation runs every 3rd cycle, configurable

### heal_local_dbs.py (script)
- One-shot async sweeper to heal/archive/rotate existing backlog
- Decided: not needed as separate service — the db.py rotation fix handles it going forward
- Script kept on branch for manual one-time cleanup of existing 261 stuck DBs on prod07
