### 4. SQLite Lock Investigation

**Observed Warning:**
```
WARNING | Silver: DB lock error, marking for reprocessing: ... - (sqlite3.OperationalError) database is locked
```

**Root Cause Analysis:**
The `feature/test-bbocax` branch uses a **hybrid architecture**:
- **Metadata DB**: SQLite (`.sqlite` files)
- **Worker shards**: SQLite shards per worker (for writes)
- **Shard merge**: DuckDB (attaches to SQLite files to merge efficiently)

**Why locks still occur:**
1. **Write operations** → routed to worker shards via `get_db_for_current_worker()`
2. **Read operations** (e.g., `file_needs_reprocessing_by_mtime()`) → still hit **canonical DB**
3. Multiple workers reading canonical DB simultaneously → occasional lock contention

**Key Code Paths:**
- `data_alchemy/utils/db.py:656` - `get_db_for_current_worker()` routes writes to shards
- `data_alchemy/handlers/handle_silver.py:405` - Uses worker shard for writes
- `data_alchemy/utils/db.py:1036-1046` - Reprocessing check reads from canonical DB

**Impact:**
- Occasional (~1/10) - NOT a blocker
- Self-healing: file marked for reprocessing → processed next cycle
- Pipeline continues normally

**Potential Future Fix (not urgent):**
Replace SQLite with DuckDB entirely for metadata storage:
- DuckDB has MVCC (Multi-Version Concurrency Control)
- Supports concurrent readers AND writers
- Would eliminate lock contention completely

### Current Database Architecture (feature/test-bbocax)
```
┌─────────────────────────────────────────────────────────────┐
│                    Parallel Processing (-p N)                │
├─────────────────────────────────────────────────────────────┤
│  Worker 1    Worker 2    Worker 3    ...    Worker N        │
│     │           │           │                  │            │
│     ▼           ▼           ▼                  ▼            │
│  ┌─────┐    ┌─────┐    ┌─────┐           ┌─────┐           │
│  │Shard│    │Shard│    │Shard│           │Shard│  (WRITES) │
│  │ _w1 │    │ _w2 │    │ _w3 │           │ _wN │           │
│  └──┬──┘    └──┬──┘    └──┬──┘           └──┬──┘           │
│     │           │           │                  │            │
│     └───────────┴───────────┴──────────────────┘            │
│                          │                                   │
│                          ▼                                   │
│              ┌───────────────────────┐                      │
│              │   DuckDB Merge        │  (End of phase)      │
│              └───────────┬───────────┘                      │
│                          │                                   │
│                          ▼                                   │
│              ┌───────────────────────┐                      │
│              │   Canonical SQLite    │  (READS also here)   │
│              │   {db_name}.sqlite    │                      │
│              └───────────────────────┘                      │
└─────────────────────────────────────────────────────────────┘
```

### Lock Contention Point
- WRITES → Worker shards (no contention)
- READS → Canonical DB (occasional contention when workers check reprocessing status)
