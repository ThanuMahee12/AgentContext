## Time Comparison Report: `--use-mtime` Feature

### Feature Added
Added `--use-mtime` flag to `time_comparison_report.py` for filesystem-based timing comparison instead of SQLite `processed_time`.

**Branch**: `feature/time-comparison-mtime-mode`
**MR**: https://git.codewilling.com/data/cwiq-pipe/data-alchemy/-/merge_requests/636 (Draft, target: dev)

### Implementation Details
```python
# get_file_mtime() - correctly converts Unix timestamp to UTC
def get_file_mtime(filepath: str) -> Optional[dt.datetime]:
    try:
        stat = os.stat(filepath)
        return dt.datetime.fromtimestamp(stat.st_mtime, tz=dt.timezone.utc)
    except OSError:
        return None

# In build_report() - minimal gold_done calculation
gold_done = (
    get_file_mtime(gold.output_filepath) if use_mtime else None
) or ensure_utc(gold.processed_time)
```

### Key Points
- `os.stat().st_mtime` returns Unix epoch (UTC-based)
- `datetime.fromtimestamp(mtime, tz=timezone.utc)` correctly converts to UTC
- SQLite `processed_time` is already stored in UTC
- Both methods produce consistent UTC times
- Includes exclusion pattern support (skip .parquet, .ndjson files)
