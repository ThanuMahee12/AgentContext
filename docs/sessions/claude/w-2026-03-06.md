#### 3. Code Review: `feature/duckdb-enhancement`

**Branch:** 57 commits ahead of dev, +2900/-84 lines, 14 files

**What it does:** DuckDB-based worker shard merging to eliminate SQLite lock contention during parallel processing. Each worker writes to its own SQLite shard; after each phase (Bronze/Silver/Gold), DuckDB merges all shards into canonical DB via UNION ALL.

**Also includes:** SQLite retention (14 days instead of 1), WAL/SHM sidecar cleanup, NFS compatibility (DELETE journal, no WAL), crash recovery (orphaned shard detection + emergency merge).

**Key files:**
- `data_alchemy/utils/worker_shards.py` (new, 235 lines) — shard path/lifecycle
- `data_alchemy/utils/duckdb_ops.py` (new, 483 lines) — DuckDB merge logic
- `data_alchemy/utils/db.py` (+321 lines) — worker routing, retention, shard init
- `data_alchemy/main.py` (+100 lines) — merge after each phase, crash recovery
- `data_alchemy/utils/parallel.py` (+77 lines) — worker ID assignment
- Handlers (bronze/silver/gold) — route writes to worker shard

**Review findings:**

| Priority | Issue |
|---|---|
| Medium | SQL injection risk in `_escape_sql` (only escapes single quotes) — use parameterized queries |
| Medium | Merge block copy-pasted 3x in main.py — extract helper |
| Medium | `bulk_read_file_state` is dead code (added but never called) |
| Medium | Two test files with overlapping scope (`test_worker_shards.py` + `worker_shards_tests.py`) |
| Low | `init_worker_shard_db` — race condition on NFS with `os.path.exists` check before `create_all` |
| Low | Merge failure raises RuntimeError without cleaning up shards |
| Low | Excessive debug logging in hot paths (per-file routing) |
| Low | `_has_shards` in duckdb_ops duplicates `has_orphaned_shards` from worker_shards |
| Low | Missing file log level changed from debug to error (fires during normal operation) |
| Low | No DuckDB merge integration tests |

**Recommendation:** Address SQL injection, code duplication, dead code, and test file naming before merge.
