#### Ansible Prod Playbook Refactoring — Planning

**Problem:** Current prod ansible playbooks have massive duplication and poor multi-host support.

**Current state:**
- `deploy-data-alchemy-prod.yml` (~500 lines) — main services, 16 active datasets
- `deploy-data-alchemy-prod06.yml` (~360 lines) — overflow (bloomberg corporate_economic_events, lseg trth_api, 2 consumer_edge signals)
- Both target same `data_alchemy_prod` host group (only `ny5-predpalch01`)
- 70+ individual `.service` files in `build/service-files/`
- Lots of commented-out dead code (bbocax, JP Morgan, GICS, dividend_forecast, ibes)
- Each service = 3 identical blocks (copy + stop + start)

**Target:** Multi-host (ny04 + ny06) with loop-based playbooks

**Key decisions made:**
1. Start with **staging refactor first** (safer, single host, no multi-host complexity)
2. Use **separate templates** for staging and prod (`data-alchemy-staging.service.j2` / `data-alchemy-prod.service.j2`) — complete isolation, changing staging can never affect prod
3. Service lists in `group_vars/` (or `host_vars/` for multi-host) — all changes go through **MR**, same control as today
4. Refactor incrementally — each step independently committable and testable

**Staging refactor plan:**
1. Create `build/inventory/group_vars/data_alchemy_staging.yml` — service list + vars (`da_env`, `da_user`, `da_base`, `da_git_branch`, `da_services`)
2. Create `build/templates/data-alchemy-staging.service.j2` — Jinja2 template replacing all individual staging `.service` files
3. Refactor `deploy-data-alchemy-staging.yml` to use loops (~760 lines -> ~50 lines)
4. Verify with `--check --diff` dry run
5. Cleanup: delete individual staging `.service` files

**Prod refactor plan (after staging verified):**
1. Update `hosts.yml` with ny04 + ny06 child groups under `data_alchemy_prod`
2. Create `host_vars/` per machine defining which services run where
3. Create `data-alchemy-prod.service.j2` template
4. Merge `prod.yml` + `prod06.yml` into single looped playbook
5. Cleanup old files, sync `live-datasets.txt`
