## Logging Context Issue (--log-prefix)

### Question
Can we add `--log-prefix` flag to capture logs per service?

### Current State
- **No `--log-prefix` flag exists** in the code
- Logging uses stdout/stderr only (loguru)
- Systemd handles log file separation via `StandardOutput/StandardError`

### Problem Found
Context variables are set **too late** - inside `init_db()` during file processing, not at startup.

**Code flow:**
```
1. main() starts
2. logger.info("Using backfill range...")     ← NO CONTEXT (no prefix)
3. logger.info("Discovering files...")        ← NO CONTEXT (no prefix)
4. ... file processing loop ...
5. init_db() called                           ← CONTEXT SET HERE (too late!)
   └── vendor_context.set(vendor)             # db.py:313
   └── dataset_context.set(ds)                # db.py:314
   └── db_name_context.set(formatted_db_name) # db.py:335
```

**Evidence in logs:**
```
# Early logs - NO prefix
2026-02-11 08:26:28 | INFO     | Using backfill range: 20251130 to 20251208
2026-02-11 08:26:28 | INFO     | Discovering files: bloomberg | bbocax_cwiq_pipe | 1.0 | ALL

# Later logs - HAS prefix (after init_db called)
2026-02-11 08:26:33 | INFO     | [bloomberg/bbocax_cwiq_pipe] Bronze: equityAsia1...
```

### Files Involved
- `data_alchemy/main.py` - CLI entry, logging config
- `data_alchemy/context.py` - Context variables defined
- `data_alchemy/utils/db.py:313-335` - Context set in `init_db()`

### Fix Required
To implement `--log-prefix` correctly:
1. Set context **early** in `main()` before any logging
2. Configure file logging based on that context
3. Then each service would auto-generate unique log files based on `db_name`

### Current Workaround
Systemd handles log separation per service file:
```ini
StandardOutput=append:.../data-alchemy-local-bbocax-corporate_actions-1.0.log
StandardOutput=append:.../data-alchemy-local-bbocax-corporate_actions-2.0.log
```

## MR #513: Bloomberg Decrypt - Stream Gzip to Disk

### Branch
`fix/bloomberg-decrypt-to-silver`

### MR Comments (from wingate.jones)
1. "this creates a temporary gzip file, lets write bytes straight to disk"
2. "lets also log that is what we are doing before and after in case it is too big for memory and we crash stuff so we have evidence if it breaks our code"

### Fix Applied
Updated `decompress_gz()` in `data_alchemy/handlers/handle_silver.py`:

**Before (loads entire file into memory):**
```python
def decompress_gz(infile: str, tofile: str) -> None:
    with open(infile, "rb") as inf, open(tofile, "w", encoding="utf8") as tof:
        decom_str = gzip.decompress(inf.read()).decode("utf-8")
        tof.write(decom_str)
```

**After (streams to disk with logging):**
```python
def decompress_gz(infile: str, tofile: str) -> None:
    input_size = os.path.getsize(infile)
    logger.info(
        "Decompressing gzip: {} ({} bytes) -> {}",
        os.path.basename(infile),
        input_size,
        os.path.basename(tofile),
    )

    # Stream decompression to avoid loading entire file into memory
    with gzip.open(infile, "rb") as gz_in, open(tofile, "wb") as out:
        while chunk := gz_in.read(8192):
            out.write(chunk)

    output_size = os.path.getsize(tofile)
    logger.info(
        "Decompression complete: {} -> {} ({} bytes -> {} bytes)",
        os.path.basename(infile),
        os.path.basename(tofile),
        input_size,
        output_size,
    )
```

### Changes
1. **Stream to disk** - Uses `gzip.open()` with 8KB chunks instead of loading all into memory
2. **Logging before** - Logs file name and input size before decompression
3. **Logging after** - Logs file names and sizes after completion
4. **Binary mode** - Writes bytes directly (`"wb"`) instead of decoding to UTF-8

### Verification
- Bloomberg decrypt tests: 4/4 passed
- Pylint: No errors
- Manual test: Streaming decompression works correctly
