## file_details_extractor.py - Multithreading Optimization

### Problem
- Script was slow on 192-core machine
- Only parallelized at directory level, not file level

### Changes Made

1. **Switched to ThreadPoolExecutor** (from ProcessPoolExecutor)
   - Better for I/O-bound work (file stat, parquet metadata reading)
   - Lower memory overhead than multiprocessing

2. **Flat file processing approach**
   - Step 1: Collect all files from all directories (fast listing)
   - Step 2: Process all files in parallel using all threads

3. **Progress tracking added**
   - Directory progress: `[4/2000] dir_name: 1,234 files`
   - File processing progress: Shows every 5% (5%, 10%, 15%...)

4. **Default workers = all CPU cores**
   - `--workers` flag to limit if needed

### Key Functions

- `collect_all_files()` - Collects files with progress callback
- `process_single_file()` - Processes one file (stat + parquet metadata)
- `process_file_tuple()` - Wrapper for parallel execution

### Usage
```bash
# Uses all 192 cores by default
python file_details_extractor.py /path/to/data -o ./output

# Limit threads if needed
python file_details_extractor.py /path/to/data -o ./output --workers 100
```

### Notes
- CSV writing left sequential (not parallelized)
- Threads are efficient here since bottleneck is disk I/O, not CPU

## tmux Resource Usage

### Key Points
- **Memory**: Main concern - scrollback buffers (~100 bytes/line)
- **CPU**: Negligible when idle
- **Storage**: Almost none (socket file only)

### Check Commands
```bash
# Find tmux processes
ps aux | grep tmux

# Get memory
ps aux | grep tmux | grep -v grep | awk '{print $6/1024 "MB", $11}'

# From inside tmux session
ps -o rss= -p $(tmux display -p '#{pid}') | awk '{print $1/1024 "MB"}'

# Session info
tmux ls
```

### Reduce Memory
```bash
# Clear scrollback
tmux clear-history

# In ~/.tmux.conf
set -g history-limit 1000
```
