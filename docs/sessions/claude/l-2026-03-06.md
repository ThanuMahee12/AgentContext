## Key Finding: Disk I/O Errors

Error log shows repeated SQLite disk I/O errors every ~18 minutes:
```
sqlite3.OperationalError: disk I/O error
[SQL: SELECT ... WHERE filemetadata.input_filepath = ? AND filemetadata.stratum = ?
      AND filemetadata.requires_reprocessing_time IS NOT NULL AND filemetadata.reprocessed_time IS NULL]
```

### Root Cause Analysis
The query pattern `requires_reprocessing_time IS NOT NULL` is NOT from bulk_read. It's from:

1. **`file_needs_reprocessing_by_mtime()`** - the fallback function called when context is None
2. **`check_for_files_needing_reprocessing()`** - called at cycle start when no new files found

### Part 1 Code Flow (Verified)
```python
# handle_bronze.py lines 106-117
if context:
    needs_processing = _check_needs_processing(fp, context)  # Uses context - NO DB
else:
    # Fallback: calls DB directly (THIS IS CAUSING ERRORS)
    from data_alchemy.utils.db import file_needs_reprocessing_by_mtime
    if not file_needs_reprocessing_by_mtime(engine, fp, "bronze"):  # DB QUERY
```

### Investigation Points
1. Context IS being built in main.py (lines 1000-1011)
2. Context IS being passed to handlers (line 1036)
3. But fallback `file_needs_reprocessing_by_mtime` is still being called somewhere
4. Possibly from `check_for_files_needing_reprocessing()` at line 829
