## Key Fixes

### 1. Empty Shards Fix (e6ffd4b)
**Problem:** `Catalog Error: Table with name filemetadata does not exist!`

Worker shards created but no data written → merge fails.

**Solution:** Added `_shard_has_table()` to filter empty shards before UNION ALL:
```python
def _shard_has_table(conn, alias, table_name="filemetadata") -> bool:
    result = conn.execute(
        f"SELECT COUNT(*) FROM information_schema.tables "
        f"WHERE table_schema = '{alias}' AND table_name = '{table_name}'"
    ).fetchone()
    return result[0] > 0

# Filter: only include shards with filemetadata table
shard_aliases = [a for a in all_aliases if _shard_has_table(conn, a)]
```

## Architecture Reminder

```
silver/YYYY/MM/DD/
├── vendor--dataset.sqlite              ← canonical
└── worker_dbs/
    ├── vendor--dataset_w001.sqlite     ← worker 1 shard
    ├── vendor--dataset_w002.sqlite     ← worker 2 shard
    └── vendor--dataset_w003.sqlite     ← worker 3 shard
```

**Flow per phase:**
1. Workers write to `worker_dbs/{name}_wXXX.sqlite`
2. Phase completes
3. DuckDB UNION ALL merge → canonical
4. Delete worker shards
5. Next phase starts fresh

## Key Learnings

1. **DuckDB UNION ALL** - Attach all shards at once, single INSERT with UNION ALL (faster than sequential)

2. **Empty shards** - Workers may create shard files but not write data → check table exists before merge

3. **threading.local()** - Correct for ThreadPoolExecutor (not ContextVar which is for asyncio)

4. **NFS issues** - "attempt to write a readonly database" often caused by NFS permissions, not code

5. **Functional programming** - Use frozen attrs, lambdas, derived properties, generators with yield from
