### 1. Yesterday's Fix Review

**Commit:** `adcbb34` - fix: decrypt Bloomberg files directly to silver instead of bronze

**Problem solved:**
- Bloomberg encrypted files (.enc) were being decrypted to bronze directory
- This polluted bronze with non-raw .gz files that lacked .md5 pairs

**Solution:**
- Changed to use `decrypt_bloomberg_file()` with silver path directly
- Files now flow: Bronze (raw .enc) → Silver (decrypted .gz)

### 2. Testing Bloomberg Encrypted Files

Tested bbocax_cwiq_pipe processing and observed:
- Bronze has: `corpPfdAsiaV2`, `calendar`, `condition_code` files
- Silver only shows: `condition_code.out` files

**Clarification:**
- `corpPfdAsiaV2` and `calendar` are NOT meant to be decrypted
- Decrypt inclusion patterns in `resc/silver_decrypt_inclusions/bloomberg.json` control which files get decrypted
- Valid patterns: `curncy_*`, `equity_*`, `pfd_exch_*`, `*Futures*`, `condition_code`, `lookup`

### 3. Test Command for Encrypted Files

```bash
uv run python -m data_alchemy.main \
    --vendor bloomberg \
    --dataset bbocax_cwiq_pipe \
    --version 1.0 \
    --backfill 1500 \
    --file-pattern ".*(curncy_|equity_|pfd_exch_|shareFutures|nonShareFutures|condition_code|lookup).*\.enc.*" \
    --test-limit 100
```

Simpler pattern:
```bash
--file-pattern ".*(curncy_|equity_|pfd_exch_|Futures).*\.enc.*"
```
