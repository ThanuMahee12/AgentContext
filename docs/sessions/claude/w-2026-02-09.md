### Session 3 — Parallelism Branch Review

#### 6. `feature/paralellism` Branch Review

Branch adds `--parallel N` / `-p N` flag for multi-threaded Bronze/Silver/Gold processing.

**Key files:**
- `data_alchemy/utils/parallel.py` — new: `parallel_process()`, `parallel_process_gold_ordered()`, `AtomicCounter`
- `data_alchemy/main.py` — wired parallel to all 3 phases
- `data_alchemy/utils/db.py` — WAL mode, QueuePool, `check_same_thread=False`, `busy_timeout=30000`

**Bottlenecks identified:**

| Priority | Issue |
|----------|-------|
| **High** | `copy_context()` shared across all threads → `RuntimeError: cannot enter context` |
| **High** | Gold ordering `can_submit()` is O(n) per file → O(n^2) with large batches |
| **Medium** | SQLite write contention (WAL helps reads, writes still serialized) |
| **Low** | `init_db()` called per-file in each worker (mitigated by cache) |

**Test run:** bbocax with 8 workers on ny5-predpalch01 — crashed with `RuntimeError` from `ctx.run()` (bottleneck #5 confirmed).

**Fix needed:** Create separate `copy_context()` per task, not one shared across all workers.

### Session 5 — fs-hunter: Compare Mode Refactor

**Repo:** `fs-hunter` (C:\Users\thanu\Downloads\fs-hunter)
**Commit:** `948ee88` pushed to both GitHub + CodeWilling

#### Problem

`compare` command was broken for its primary use case — comparing files between two different base paths (e.g., `/sf/data` vs `/sf/proj/data_alchemy/assets/cdp_out`). `compute_delta()` diffed on `full_path`, so every file appeared as both "added" and "removed" since the prefixes differ.

#### Fix: Join-based comparison on `relative_path`

**Files modified:** `metadata.py`, `compare.py`, `main.py`

1. **metadata.py** — Removed `d.pop("relative_path", None)` from `to_dict()` so `relative_path` appears in all DataFrames
2. **compare.py** — Full rewrite:
   - `compute_delta()` → `compute_comparison()` — outer join on `relative_path`
   - Status: `match` / `differ` / `missing_in_source` / `missing_in_target`
   - `format_time_delta()` — `+HH:MM:SS` (target newer) / `-MM:SS` (source newer) / empty (equal or N/A)
   - `write_compare_summary()` — updated with match/differ/missing counts
   - `write_delta_metrics()` — overview, by_status, by_extension, latency stats
   - `write_metrics_jsonl()` — new, one JSON line per time bucket
3. **main.py** — Updated compare command to use new engine

#### Output Structure

```
fs_hunter/compare/YYYYMMDD_HHMMSS/
├── s_result.csv          # Source scan (includes relative_path)
├── t_result.csv          # Target scan (includes relative_path)
├── delta.csv             # Side-by-side joined comparison (15 columns)
├── _summary.csv          # match/differ/missing counts
├── delta_metrics.json    # overview, by_status, by_extension, latency
└── metrics.jsonl         # Time-bucketed JSONL
```

#### delta.csv Columns (15)

`relative_path`, `status`, `source_mtime`, `target_mtime`, `mtime_delta`, `source_ctime`, `target_ctime`, `ctime_delta`, `source_size`, `target_size`, `size_delta`, `checksum`, `source_full_path`, `target_full_path`

#### Notes

- Empty `mtime_delta` = either identical timestamps (0 diff) or one side missing
- `checksum` = `Match`/`Mismatch`/`N/A` (N/A when hash unavailable or one side missing)
- Tested on server with Bloomberg bbocax compare at `/home/bthanujan.mahendran/output/fs_hunter/compare/20260209_185739/`
