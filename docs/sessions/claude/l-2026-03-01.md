## Data-Alchemy Architecture Deep Dive

### Medallion Architecture
```
Raw (env*) → Bronze (YYYY/MM/DD/HHMMSS--) → Silver (work/) → Gold (raw/*.lz4)
```

### Core Components

| Component | Purpose |
|-----------|---------|
| `handle_bronze.py` | Copy raw → bronze, metadata, MD5, date partition |
| `handle_silver.py` | Extract/decompress, Bloomberg decrypt |
| `handle_gold.py` | Grabber map transformations, lz4 compression |
| `grabber_maps/*.json` | Gold layer transformation rules |
| `FileMetadata` model | SQLite tracking for all layers |

### Key CLI Flags
| Flag | Purpose |
|------|---------|
| `--watch` | Continuous mode |
| `--interval N` | Watch interval (seconds) |
| `--file-pattern` | Regex filter for files |
| `--db-name` | Custom DB name template |
| `-p N` | Parallel workers (-1 = all CPUs) |
| `--backfill N` | Hours lookback |

### Envelope System
- Files in `env*` directories (env0, env1, env2...)
- All envelopes processed, not just latest
- Bronze handles uniqueness via mtime-based timestamp prefix

### Database
- Per-date SQLite in silver directory
- Tracks: vendor, dataset, version, stratum, timestamps, paths
- Resupply detection via mtime comparison
- DB lock recovery with `requires_reprocessing_time`

## DB Lock Recovery Investigation

### Issue Observed
```
Created reprocessing record: .../bronze/2026/02/20/030452-0500--govtAgencyReglAsia.parquet (silver)
```

### Root Cause
This is **normal DB lock recovery behavior**, not an error:

1. A previous run encountered a **SQLite database lock** (another process using the DB)
2. Files that couldn't be processed due to the lock are marked for reprocessing
3. Since no record existed (lock prevented initial write), new records created with `requires_reprocessing_time` set

### Why It Happens
- Another pipeline instance running simultaneously
- Previous run crashed/interrupted while holding DB lock
- Multiple parallel workers (`-p -1`) competing for same DB

### Code Location
- `data_alchemy/utils/db.py:638` - `mark_for_reprocessing()` function
- `data_alchemy/main.py:1265` - Called when silver DB lock detected
- `data_alchemy/main.py:1465` - Called when gold DB lock detected

### Recovery Commands
```bash
# Check for other running data-alchemy processes
ps aux | grep data_alchemy

# Check for stale DB locks
lsof /sf/proj/data_alchemy/devData/bthanujan.mahendran/data/bloomberg/bbocax_cwiq_pipe/1.0/silver/2026/02/20/*.db 2>/dev/null

# Force reprocess by deleting SQLite DBs
rm /sf/proj/data_alchemy/devData/bthanujan.mahendran/data/bloomberg/bbocax_cwiq_pipe/1.0/silver/2026/02/20/*.db
```

### Note on Backfill
Files from Feb 20 won't be processed with default backfill (24h). To process old files:
- `--backfill 720` (30 days)
- `--backfill-range 20260220:20260220` (specific date)
