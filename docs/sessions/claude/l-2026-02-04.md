### Bug Found: Map Index Missing in Sequential Mode

**Issue:** Files with date suffix (e.g., `shareFuturesExtendedOpenAsia1.dif.20260126`) show `Map[-1] (unknown)` in sequential mode but proper `Map[68]` in parallel mode.

**Observed behavior:**
- Sequential: `.parquet` files get proper Map indices (Map[92-102]), `.dif/.out/.dlt` files get Map[-1]
- Parallel: ALL files get proper Map indices
- Files still route to correct destinations in both modes

**Root cause hypothesis:**
When `max_workers == 1`, `parallel_process_gold_ordered` skips the pre-computation step that calls `get_destinations` -> `apply_grabber_maps`. This pre-computation may have a side effect that makes subsequent grabber map matching work correctly.

**Code location:** `data_alchemy/utils/parallel.py:225-229`
```python
# Sequential processing if max_workers == 1
if max_workers == 1:
    return parallel_process(
        silver_files, process_func, 1, phase_name, shutdown_flag
    )
```

**Grabber map files affected:** All 6 `futures_extended` grabber maps share the same key `("bloomberg", "1.0", "bbocax_cwiq_pipe")` and get merged at load time.

**Status:** Bug identified, needs further investigation
